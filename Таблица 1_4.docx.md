**Общие правила связей**

1. **Основные связи задаются редактором вручную.** Для MVP это проще, надёжнее и дешевле автоматического подбора по тегам.   
2. **Связь должна отображаться в обе стороны**, когда это содержательно оправдано. Например, если кейс связан с инструментом, в карточке кейса показывается инструмент, а в карточке инструмента — соответствующий кейс.   
3. **Один материал может иметь несколько связанных материалов** одного типа.   
4. **Связанный материал выбирается из уже созданных и опубликованных материалов** соответствующего типа.   
5. При снятии связанного материала с публикации ссылка на него не должна отображаться на публичной странице.   
6. Порядок связанных материалов желательно задавать вручную либо использовать установленный порядок сортировки.   
7. Для MVP блок «Похожие материалы» формируется на основе ручных связей. Автоматические рекомендации по тегам можно оставить для второй очереди.

**Обязательный минимум для MVP**

Для MVP обязательно обеспечить:

* создание и редактирование всех восьми типов материалов;   
* сохранение черновиков;   
* публикацию и снятие с публикации;   
* заполнение обязательных и множественных полей;   
* загрузку изображений и файлов;   
* выбор значений из справочников;   
* установку связей между материалами;   
* автоматическую фиксацию даты изменения;   
* поиск материалов в административной части;   
* разделение прав редактора и администратора;   
* управление базой без постоянного обращения к разработчику. 

**Функции, которые можно оставить за пределами MVP**

При ограниченном бюджете можно не включать в первую версию:

* автоматическое сохранение;   
* полноценную историю версий;   
* сложные массовые операции;   
* автоматическое формирование связей;   
* расширенную фильтрацию в административной части;   
* отложенную публикацию;   
* ручную сортировку каждого связанного блока;   
* отдельные описания для каждого загруженного файла;   
* сложную систему редакционного согласования.
